# 服务器后端环境检查文档：录音复盘链路部署与排查

日期：2026-06-17  
项目根目录：`/home/CareerInvestmentCopilot` 或服务器实际 clone 目录  
本地项目根目录：`D:\Study\rh\zhitouCopilot\CICopilot\CareerInvestmentCopilot-feature-initial-upload`

## 1. 目标

本文件用于在服务器 clone 仓库后，配置并检查后端运行环境，使本机 Windows 前端可以调用服务器后端，跑通“面试录音复盘”链路。

目标链路：

```text
Windows 本机前端
-> http://120.79.220.126:8001 后端
-> 服务器 /home/public/audio/user-{userId}/ 保存录音
-> 生成公网 URL：http://120.79.220.126:8001/audio/user-{userId}/xxx.m4a
-> DashScope ASR 下载该 URL
-> ASR 转写
-> DeepSeek 清洗总结
-> 写入 PostgreSQL RealInterviewRecord
-> 前端展示复盘结果
```

## 2. 当前问题理解

当前本机同时运行前端和后端时，录音上传会保存到 Windows 本机路径，例如：

```text
D:\home\public\audio\user-1\xxx.m4a
```

DashScope ASR 是云服务，不能读取 Windows 本地磁盘文件，也不能访问 `localhost` 或 `D:\...` 路径。

因此本地后端无法完整跑通录音复盘链路。

正确做法是：

```text
前端可以继续运行在 Windows 本机
但后端必须运行在公网服务器
录音文件必须保存到服务器
音频 URL 必须是公网可访问的 http://120.79.220.126:8001/audio/...
```

这个方法是可行的。

## 4. 服务器后端环境变量

后端目录：

```bash
cd /home/CareerInvestmentCopilot/ai-job-backend
```

```bash

```

必须检查以下配置。

### 4.1 基础配置

```env
PORT=8001
JWT_SECRET=replace-with-a-long-random-secret
CORS_ORIGIN=http://localhost:3000
```

说明：

- `PORT=8001`：后端监听 8001。
- `CORS_ORIGIN=http://localhost:3000`：允许 Windows 本机前端访问服务器后端。
- 如果本机前端端口不是 3000，需要改成实际端口。

### 4.2 数据库配置

如果后端直接连服务器 Docker Postgres，推荐：

```env
DATABASE_URL=postgresql://zhitou_app:<URL编码后的密码>@127.0.0.1:5432/zhitou_copilot?schema=public
```

如果后端和 Postgres 在同一个 Docker Compose 网络里，可能是：

```env
DATABASE_URL=postgresql://zhitou_app:<URL编码后的密码>@postgres:5432/zhitou_copilot?schema=public
```

注意：

如果密码中有 `/`，必须 URL 编码为 `%2F`。

示例格式：

```text
原始密码：<真实数据库密码，不提交 GitHub>
编码密码：<URL 编码后的真实数据库密码，不提交 GitHub>
```

### 4.3 简历上传目录



### 4.4 录音上传目录

### 4.5 ASR 公网 URL



## 6. 后端监听检查

后端启动后，在服务器执行：

```bash
ss -lntp | grep 8001
```

期望看到类似：

```text
LISTEN 0 511 0.0.0.0:8001
```

如果只监听：

```text
127.0.0.1:8001
```

外部公网可能访问不到。

NestJS 默认 `app.listen(PORT)` 通常可以监听所有网卡，但仍建议用 `ss` 确认。

## 7. 健康检查

### 7.1 服务器本机访问

在服务器执行：

```bash
curl http://127.0.0.1:8001/health
```

如果不通，说明后端没有正常启动。

### 7.2 服务器公网访问

在服务器执行：

```bash
curl http://120.79.220.126:8001/health
```

如果 `127.0.0.1` 通但公网 IP 不通，检查：

- 后端是否监听 `0.0.0.0`
- 服务器防火墙
- 云服务器安全组
- 端口 8001 是否开放

### 7.3 Windows 本机访问

在 Windows PowerShell 执行：

```powershell
Invoke-WebRequest -Uri http://120.79.220.126:8001/health -UseBasicParsing
```

如果 Windows 本机访问不通，前端也一定访问不通。

## 12. 常见错误与原因

### 12.1 前端显示 Failed to fetch

原因通常是：

- `VITE_API_BASE_URL` 指向了不可访问的后端
- 服务器 8001 没启动
- 安全组没开放 8001
- 后端 CORS 不允许当前前端来源

检查：

```powershell
Invoke-WebRequest -Uri http://120.79.220.126:8001/health -UseBasicParsing
```

### 12.2 缺少公网可访问的 audioUrl

原因：

后端没有生成公网音频 URL。

检查 `.env`：

```env
ASR_PUBLIC_BASE_URL=http://120.79.220.126:8001
```

检查后端运行环境是否真的读取到了该变量。

### 12.3 FILE_DOWNLOAD_FAILED

原因：

DashScope 访问音频 URL 失败。

检查：

```bash
curl -I http://120.79.220.126:8001/audio/user-1/xxxx.m4a
```

必须公网可访问，不能只在服务器本机可访问。

### 12.4 登录 500

原因可能是：

- 数据库未同步 Prisma schema
- `User` 表不存在
- `DATABASE_URL` 指向错误数据库
- Prisma Client 未生成

检查：

```bash
npx prisma db push
npx prisma generate
```

查看后端日志：

```bash
docker logs --tail 100 zhitou-backend
```

或如果是 npm 直接启动，查看当前终端日志。

## 13. 推荐联调顺序

不要一上来直接测录音。

推荐顺序：

1. 服务器后端启动：

```bash
curl http://127.0.0.1:8001/health
```

2. Windows 能访问服务器后端：

```powershell
Invoke-WebRequest -Uri http://120.79.220.126:8001/health -UseBasicParsing
```

3. Windows 前端切服务器 API：

```env
VITE_API_BASE_URL="http://120.79.220.126:8001"
```

4. 前端登录成功。

5. 前端查询首页、简历、知识库等普通接口成功。

6. 手动测试静态音频 URL：

```text
http://120.79.220.126:8001/audio/user-test/ping.txt
```

7. 前端上传录音。

8. 服务器确认音频文件落盘。

9. 检查 `RealInterviewRecord` 是否写入数据库。

10. 检查前端是否展示复盘结果。

## 14. 最终结论

你的方案是可行的：

```text
代码上传 GitHub
-> 服务器 clone/pull 最新代码
-> 服务器配置后端 .env
-> 服务器启动后端 8001
-> Windows 本机运行前端
-> 前端 API 指向 http://120.79.220.126:8001
-> 测试录音复盘
```

这个方案能解决本地后端保存音频到 `D:\home\public\audio`，导致 DashScope 无法下载的问题。

关键前提只有一个：

```text
服务器后端 8001 必须能被 Windows 本机和 DashScope 公网访问。
```

如果 `http://120.79.220.126:8001/health` 在 Windows 本机访问不通，就不要继续测录音，先修服务器后端访问问题。
