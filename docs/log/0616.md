## 3. 今日排查的问题

### 3.1 录音复盘上传报错

报错：

```text
缺少公网可访问的 audioUrl，DashScope ASR 不能直接读取本地上传文件
```

原因：

当时前端请求的是本地 Windows 后端：

```text
frontEnd localhost:3000
-> ai-job-backend localhost:3001
```

录音文件保存到了 Windows 本地路径。DashScope ASR 是云服务，不能读取 Windows 本地磁盘文件，所以无法下载音频。

正确的录音 ASR 链路应该是：

```text
前端 localhost:3000
-> 服务器后端 http://120.79.220.126:8001
-> 服务器 /home/public/audio/user-{userId}/xxx.m4a
-> http://120.79.220.126:8001/audio/user-{userId}/xxx.m4a
-> DashScope ASR 下载公网音频 URL
```

### 3.2 改前端 API 到服务器后登录 Failed to fetch

为了让录音上传到服务器，曾将：

```env
VITE_API_BASE_URL="http://120.79.220.126:8001"
```

但随后登录时报：

```text
Failed to fetch
```

排查结果：

本机访问服务器后端失败：

```text
http://120.79.220.126:8001/health
http://120.79.220.126:8001/auth/login
```

均无法连接远程服务器。

因此，这不是账号密码错误，而是前端指向了当前不可访问的服务器后端。

临时恢复本地测试配置：

```env
VITE_API_BASE_URL="http://localhost:3001"
```

这能恢复本地登录、注册、简历、模拟面试等普通功能测试。

### 3.3 本地后端登录接口返回 500

排查时发现：

- `OPTIONS http://localhost:3001/auth/login` 返回 204，说明 CORS 预检正常。
- `POST http://localhost:3001/auth/login` 返回 500。

这说明：

1. 本地后端端口是通的。
2. 跨域配置是通的。
3. 但登录业务内部仍可能有数据库、Prisma schema 或账号数据问题。

这部分后续需要继续查看后端登录时报出的 `GlobalExceptionFilter` 具体日志。

### 4.2 录音复盘完整链路测试

录音复盘不能只靠本地后端完整跑通。

必须满足：

```text
前端 localhost:3000
-> 服务器后端 120.79.220.126:8001
-> 服务器文件目录 /home/public/audio
-> DashScope 下载公网音频 URL
```

服务器后端 `.env` 至少需要：

```env
PORT=8001
AUDIO_UPLOAD_DIR=/home/public/audio
ASR_PUBLIC_BASE_URL=http://120.79.220.126:8001
CORS_ORIGIN=http://localhost:3000
```

前端 `.env.local` 才能切为：

```env
VITE_API_BASE_URL="http://120.79.220.126:8001"
```

目前问题是服务器 `120.79.220.126:8001` 从本机无法访问，所以暂时不能切。
