# 0701 工作日志：投递管理前移后移交互修复

## 今日目标

修复投递管理页面中「已投递」板块岗位卡片点击「前移」「后移」后没有明显响应的问题，并优化状态移动过程中的用户反馈。

## 问题现象

在投递管理页面中，展开已投递岗位卡片后：

- 点击「前移」没有任何提示。
- 点击「后移」后页面看起来没有变化。
- 用户无法判断是按钮不可用、接口失败，还是状态已经更新但页面没有刷新。

## 根因分析

### 岗位状态没有映射到前端

后端 `/jobs` 和 `PATCH /jobs/:id` 会返回岗位状态字段 `status`，但前端 `mapBackendJob` 只映射了基础字段：

```text
id
title
company
description
matchScore
tag
```

没有映射：

```text
status
priority
salary
location
notes
sourceUrl
updatedAt
```

因此即使后端已经把状态从 `applied` 更新为 `interviewing`，前端拿到更新结果后仍然没有 `status`，`DeliveryManagementView` 会继续把该岗位按默认逻辑归到「已投递」。

### 边界状态缺少反馈

原逻辑会把越界移动 clamp 到当前阶段：

```text
已投递 + 前移 -> 已投递
Offer + 后移 -> Offer
```

如果目标状态和当前状态一致，函数直接 return，页面没有任何提示。

## 修复内容

### 补全岗位数据映射

涉及文件：

```text
frontEnd/src/api/backend.ts
```

调整 `mapBackendJob`：

- 公司名为空时兜底为「未知公司」。
- 映射岗位详情字段：
  - `sourceUrl`
  - `salary`
  - `location`
  - `notes`
  - `priority`
  - `status`
  - `updatedAt`
- 保留原有 `matchScore` 和 `tag` 计算逻辑。

修复后，状态推进接口返回的新状态能够真正进入前端列表，卡片会移动到对应板块。

### 优化前移后移交互

涉及文件：

```text
frontEnd/src/components/DeliveryManagementView.tsx
```

新增能力：

- 为投递阶段增加中文标签映射：

```text
applied -> 已投递
interviewing -> 面试中
offer -> Offer
```

- 点击「后移」时先进行乐观更新：
  - 已投递移动到面试中
  - 面试中移动到 Offer
- 后端接口成功后用后端返回值覆盖本地状态。
- 后端接口失败时回滚到原状态，并显示错误提示。
- 移动过程中按钮显示「移动中」并禁用，避免重复点击。
- 边界按钮置灰：
  - 已投递不能再前移
  - Offer 不能再后移
- 顶部增加轻提示：
  - 成功：`已移动到面试中` / `已移动到Offer`
  - 边界：`已经是第一个阶段` / `已经是最后一个阶段`
  - 失败：显示接口错误信息或通用失败提示

## 用户体验变化

修复前：

```text
点击按钮 -> 页面无变化 -> 用户以为按钮失效
```

修复后：

```text
点击后移 -> 卡片立即移动到下一板块 -> 顶部提示移动成功
```

边界状态下：

```text
已投递的前移按钮置灰
Offer 的后移按钮置灰
```

接口失败时：

```text
卡片回到原板块，并显示错误提示
```
