## 四、后端端口占用问题说明

### 问题现象


### 判断原因

这说明 `8001` 端口上已经有一个后端 Node/Nest 进程在运行。再次启动后端时，新进程无法绑定同一个端口，因此抛出 `EADDRINUSE`。

## 二、题目进度一直停留在 1/5 的问题

### 问题现象

专业模拟面试过程中，虽然 AI 已经说出：

```text
好的，那我们换个话题。
```

但前端仍显示：

```text
第 1/5 题
当前题：专业能力
```

并且后续对话仍然归属到第 1 题，导致第 2、3、4、5 题没有完整进入。

### 根因分析

Graph 的 Strategist 已经具备切题策略：

- 同一节点连续深挖约 3 轮后返回 `switch_topic`。
- 总轮次达到阈值后返回 `wrap_up`。

但 `InterviewsService` 没有把 Graph 的 `action` 接到会话状态：

- `switch_topic` 后没有推进 `currentQuestion`。
- 下一条 AI 消息仍绑定旧的 `questionId`。
- 前端只看 `currentQuestion` 和 `questionId`，所以一直显示 `1/5`。
- 报告生成按 `questionId` 聚合问答，旧数据会把大量对话都归到 `q-1`。

### 修复内容

新增专业模式转场处理：

```text
resolveProfessionalGraphTransition()
```

核心规则：

- `action === switch_topic` 时推进到下一道未跳过题目。
- 如果 `action === wrap_up` 但后面还有题，则优先推进到下一题，不直接结束。
- 如果 `action === wrap_up` 且后面没有题，才结束会话。
- AI 下一条消息绑定推进后的 `questionId`。
- 切到下一题后，`interviewState.stage` 重置到新节点起点，避免下一轮马上进入收尾。

补充单测：

```text
专业模式切换话题时会推进 currentQuestion 并把下一问绑定到新题目
```

验证点：

- `currentQuestion` 从 1 推进到 2。
- 下一条 AI 消息绑定 `q-2`。
- `messageType` 为 `topic_switch`。

### Nginx 代理建议

在 `/etc/nginx/sites-enabled/default` 中增加：

```nginx
location /api/ {
    proxy_pass http://127.0.0.1:3000/;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

重载：

```bash
nginx -t
systemctl reload nginx
```

验证：

```bash
curl -I http://127.0.0.1:3000/health
curl -I http://127.0.0.1:8080
curl -I http://127.0.0.1:8080/api/health
```
