## 1. 文档目标

当前项目正在更换前端界面，新 UI 的功能块、页面结构和交互流程已经和旧前端不同。工程上应先把“前端功能块”和“后端接口/数据库落点”理清楚，再逐个连接。

可以理解为：

```text
前端页面按钮/表单
-> 前端 API 函数
-> 后端 Controller
-> 后端 Service
-> Prisma Model
-> 数据库表/字段
```

本文档用于记录当前前后端接口现状、已接线功能、未接线功能和后续适配优先级。

适配状态：已接入。



```json
}
```

```text

```

## 18. 工程原则

后续每接一个新 UI 功能，应先写清楚：

```text
1. 前端入口在哪个组件
2. 用户触发什么动作
3. 调哪个 frontend api 函数
4. 对应哪个 HTTP 接口
5. 请求参数是什么
6. 后端哪个 Controller 接
7. 后端哪个 Service 处理
8. 写入/读取哪个 Prisma Model
9. 数据库落在哪个表哪个字段
10. 前端拿响应后更新哪个 state
```

这样就不会出现“页面做完了，但数据不知道去哪了”的情况。
