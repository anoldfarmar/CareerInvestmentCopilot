# 密钥管理规范

即使 GitHub 仓库是私有仓库，也禁止提交真实 `.env`、API Key、服务器密码、证书私钥和真实用户数据。

## 为什么私有仓库也不能放 `.env`

- 私有仓库也有成员账号被盗、权限误配、插件授权过大等风险。
- GitHub Actions、日志、第三方工具可能意外打印环境变量。
- 一旦密钥进入 Git 历史，删除文件并不等于删除历史记录。
- 后续仓库可能被误设为公开，或代码被复制到其他地方。
- 成员离队后，密钥轮换会变得麻烦。

## 正确做法

- 仓库只提交 `.env.example`。
- 真实 `.env` 只放在服务器本地。
- CI/CD 使用 GitHub Secrets。
- 团队成员本地开发优先使用 `AI_ENABLE_MOCK=true`。
- 需要联调真实模型时，成员连接共享测试服务器，而不是每个人持有蓝心 API Key。
- 如必须本地持有密钥，通过私下安全渠道发送，不要通过 Git、Issue、PR、群公告、截图传播。

## 泄露后的处理

如果密钥被提交过：

1. 立即在供应商平台禁用或轮换密钥。
2. 删除仓库中的明文文件。
3. 清理 Git 历史。
4. 通知所有成员重新拉取干净仓库。
5. 检查 Actions 日志和部署日志。

最稳妥的原则：密钥宁可多配一次，也不要进 Git 历史一次。
