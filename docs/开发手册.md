# 职投 Copilot 团队开发手册 v1.0

本文档用于约束职投 Copilot 复赛 Demo 的产品边界、技术路线、接口格式、代码结构、数据库设计、AI 调用方式、Git 协作和 APK 演示流程。

本手册的读者包括团队成员，也包括团队成员使用的编程 AI。任何人或 AI 在写代码前，都应先阅读本文档；如果本文档与临时想法冲突，以本文档为准，除非团队明确更新本文档。

## 1. 项目定位

### 1.1 产品一句话

职投 Copilot 是一款面向应届生、实习生、校招生、转岗求职者和高频投递人群的 AI 求职复盘助手。

产品核心不是“帮用户自动海投”，也不是“简单生成一份简历”，而是围绕用户的简历、岗位 JD、模拟面试和真实面试复盘数据，构建个人求职知识库，让每一次面试都成为下一次求职优化的训练数据。

### 1.2 复赛 Demo 核心闭环

复赛阶段优先展示以下闭环：

1. 用户上传简历或填写个人档案。
2. 系统解析简历，形成结构化用户画像。
3. 用户导入目标岗位 JD，系统计算岗位匹配度并给出差距分析。
4. 用户进行模拟面试，系统基于简历、JD 和历史复盘数据生成问题。
5. 用户上传真实面试录音或手动输入复盘内容。
6. 系统完成 ASR 转写、内容清洗、问题提取、短板分析和改进建议生成。
7. 复盘结果保存到个人求职知识库，并反向作用于模拟面试和简历优化。

### 1.3 复赛 Demo 必做功能

复赛 Demo 应优先完成这 4 个主功能：

- 面试复盘：录音上传、ASR 转写、结构化复盘、保存知识库。
- 模拟面试：根据简历、岗位 JD、复盘短板生成面试问题，并对回答给出评分和建议。
- 简历优化：上传或输入简历，解析为结构化档案，给出修改建议和优化版本。
- 岗位匹配：导入或选择岗位 JD，计算匹配度、能力差距和准备建议。

投递管理、提醒、看板、岗位爬虫、批量岗位库属于增强功能。时间不足时，只做能够支撑主闭环的最小版本。

### 1.4 明确不做或弱化的内容

复赛 Demo 不追求以下内容：

- 不做高并发、大规模用户系统。
- 不做复杂权限体系。
- 不做自动批量投递，避免招聘平台合规风险。
- 不做完整商业化支付系统。
- 不做全网实时岗位爬虫，先使用种子岗位库、手动导入 JD 或少量公开岗位样例。
- 不做模型微调。优先使用 prompt、RAG、结构化输出和业务流程编排。

如赛方明确禁止某类模型改造，应以赛方规则为准。Prompt 设计、接口编排、RAG 检索和结构化输出通常不等同于模型微调，但提交前必须核对赛事 PDF 和官方通知。

## 2. 推荐技术路线

### 2.1 总体架构

复赛阶段推荐采用：

```txt
Android App
  -> 云服务器 FastAPI Backend
    -> SQLite Database
    -> File Storage
    -> AI Service Adapter
      -> 蓝心大模型 API
      -> ASR / TTS / NLP / Vision
```

默认架构是“手机 App + 云服务器后端 + 蓝心大模型 API”。手机 App 只负责用户交互、录音、文件选择、状态展示和结果展示；文档解析、模型调用、Prompt 编排、数据库读写、任务状态管理都放在云服务器后端完成。

当前服务器配置：

```txt
通用型
2 vCPU
2 GiB 内存
ESSD 云盘 40 GiB
```

该配置足够支撑复赛 Demo 和 4 人以内试用，但它不是用来本地部署大语言模型的机器。正确用法是把它作为业务编排服务器：运行 FastAPI、保存文件、管理 SQLite 数据库、调用蓝心大模型 API，并把结构化结果返回手机。

该配置适合：

- FastAPI 后端服务。
- SQLite 数据库。
- 少量 PDF/DOCX/图片/音频文件上传和解析。
- 调用蓝心文本生成、ASR、OCR、TTS 等云端能力。
- 少量演示数据和最多 4 人试用。

该配置不适合：

- 本地部署大语言模型。
- 本地运行大型 Whisper/ASR 模型。
- 高并发服务。
- 大量长音频同时转写。
- 大规模视频生成或复杂视频处理。
- 长期存储大量真实简历和录音文件。

### 2.2 移动端路线

推荐移动端使用 Android Studio 开发原生 Android APK。

建议技术：

- 语言：Kotlin。
- UI：Jetpack Compose。
- 网络请求：Retrofit 或 Kt or Client，二选一，推荐 Retrofit。
- 本地轻量状态：DataStore。
- 权限：Android 运行时权限申请。
- 文件选择：Android 系统文件选择器。
- 录音：MediaRecorder 或 AndroidX 相关封装。

这样做的原因：

- APK 产物明确，可以安装到手机。
- 录音、文件导入、权限申请、真机调试路径清晰。
- Android Studio 是 APK 构建和调试的主工具。
- 复赛只需 4 人以内使用，不需要先做跨平台复杂工程。

### 2.3 Stitch、Figma 和 Android Studio 的关系

Stitch 可以用于生成移动端交互原型和 UI 页面方案。Figma 可以用于统一视觉、组件、间距和页面流转。Android Studio 用于真正实现 APK。

推荐流程：

```txt
Stitch 生成界面原型
  -> 导入或整理到 Figma
  -> 团队确认页面结构、视觉规范、交互状态
  -> Android Studio 使用 Kotlin + Jetpack Compose 实现
  -> 连接 FastAPI 后端真实接口
```

注意：

- Stitch 不是 Android 工程本身。
- Figma 也不是 Android 工程本身。
- Stitch 生成的 React、HTML 或设计稿，不能直接等价为 APK。
- 如果 Stitch 输出的是 Web 前端代码，可以作为视觉参考或原型，不建议直接让 Android Studio“自动转换”为可维护的原生代码。
- 若后续发现团队没有 Android 开发能力，可以备选 React/Vite + Capacitor 打包 APK，但该路线对录音、文件权限和原生体验仍需额外处理。

本项目当前主路线定为：Stitch/Figma 负责设计，Android Studio 原生实现 APK。

### 2.4 后端路线

后端推荐使用 Python FastAPI。

后端默认部署在云服务器上，对 Android App 提供公网 API。开发阶段可以在本机启动 FastAPI 调试，但最终 Demo APK 应请求云服务器地址，而不是请求开发者电脑的局域网 IP。

建议技术：

- Web 框架：FastAPI。
- ASGI 服务：Uvicorn。
- 数据库 ORM：SQLModel 或 SQLAlchemy，推荐 SQLModel 入门更直观。
- 数据库迁移：Alembic。
- Demo 数据库：SQLite。
- 后续可升级数据库：PostgreSQL。
- 文件解析：PDF、DOCX、图片 OCR 分模块实现。
- API 文档：FastAPI 自动生成 OpenAPI 和 `/docs`。

FastAPI 很适合本项目，因为：

- Python 更适合文件解析、AI 调用、数据处理。
- FastAPI 自动生成接口文档，方便前端和 AI 阅读。
- Pydantic 可以强约束请求和响应结构。
- Demo 阶段开发效率高。

### 2.5 数据库路线

复赛 Demo 使用 SQLite，数据库文件建议放在服务器后端目录：

```txt
data/zhitou_copilot.sqlite3
```

原因：

- 不需要安装数据库服务。
- 适合 2 vCPU / 2 GiB 内存的小服务器。
- 方便备份和迁移。
- 足够支持 4 人以内 Demo。
- 能学习完整数据库建模、ORM、迁移和查询流程。

注意：

- SQLite 数据库文件必须定期备份。
- SQLite 文件和上传文件目录不要放在会被重新部署清空的临时目录。
- 如果后续需要长期公网运行、多人频繁写入或更稳定的线上服务，再切换 PostgreSQL。

可选备份策略：

```txt
每天备份 data/zhitou_copilot.sqlite3
每天备份 uploads/ 中仍需保留的演示文件
比赛前手动导出一份完整备份
```

### 2.6 AI 模型路线

主模型供应商使用赛事方提供的蓝心大模型。

必须建立统一的 AI Service Adapter，不允许任何页面、接口或个人模块直接散落调用蓝心大模型 API。

蓝心大模型 API Key 只能放在云服务器后端的 `.env` 中，绝对不能写入 Android App、Stitch 页面、Figma 标注或前端代码。APK 可以被反编译，如果把密钥放进手机端，会有泄露风险。

统一封装层负责：

- 文本生成。
- ASR 语音识别。
- TTS 语音合成。
- OCR 或视觉理解。
- 自然语言处理。
- 结构化 JSON 输出。
- Prompt 版本管理。
- AI 调用日志记录。
- 错误重试和降级策略。

如蓝心某项能力暂时不可用，可以允许备用供应商，但必须走同一套 `AIService` 抽象接口，不能在业务代码里写多套调用格式。

## 3. 仓库结构规范

建议使用单仓库管理，结构如下：

```txt
project/
  apps/
    android/
    backend/
  docs/
    开发手册.md
    api规范.md
    演示脚本.md
  samples/
    resumes/
    job_descriptions/
    audios/
  scripts/
  .github/
    ISSUE_TEMPLATE/
    pull_request_template.md
  README.md
```

目录职责：

- `apps/android`：Android Studio 工程。
- `apps/backend`：FastAPI 后端工程。
- `docs`：开发规范、API 说明、演示脚本、会议结论。
- `samples`：演示用简历、岗位 JD、录音样例。禁止放真实隐私材料。
- `scripts`：辅助脚本，例如初始化数据库、导入样例岗位。
- `.github`：Issue 模板、PR 模板和 GitHub Actions。

如果当前还没有代码工程，先创建 `docs`，等技术路线确认后再创建 `apps/android` 和 `apps/backend`。

### 4.2 后端启动命令

本机开发调试：

```powershell
cd apps/backend
uvicorn app.main:app --reload --host 127.0.0.1 --port 8001
```

服务器部署调试：

```powershell
cd apps/backend
uvicorn app.main:app --host 0.0.0.0 --port 8001
```

正式服务器不建议长期直接裸跑 `uvicorn`。后续部署时建议使用 systemd、Supervisor、Docker Compose 或云平台进程管理工具托管服务，并在前面配置 Nginx 反向代理和 HTTPS。

推荐线上访问形态：

```txt
https://api.你的域名.com
```

如果暂时没有域名，可以先用：

```txt
http://服务器公网IP:8001
```

比赛正式演示前，优先配置域名和 HTTPS。Android 端默认可能限制明文 HTTP 请求，使用 HTTPS 能减少配置问题，也更接近真实应用。

本地真机调试时，如果手机要访问开发者电脑上的后端，才需要使用电脑局域网 IP：

```txt
http://电脑局域网IP:8001
```

Android 手机不能用 `127.0.0.1` 访问电脑后端。手机里的 `127.0.0.1` 指手机自己。

### 4.3 环境变量

后端必须提供 `.env.example`，禁止提交真实密钥。

示例：

```txt
APP_ENV=development
APP_NAME=zhitou-copilot
API_BASE_URL=http://127.0.0.1:8001
PUBLIC_API_BASE_URL=http://服务器公网IP:8001
ALLOW_ORIGINS=*

DATABASE_URL=sqlite:///./data/zhitou_copilot.sqlite3
UPLOAD_DIR=./uploads
MAX_UPLOAD_MB=100

LANXIN_API_BASE_URL=
LANXIN_API_KEY=
LANXIN_TEXT_MODEL=
LANXIN_ASR_MODEL=
LANXIN_TTS_MODEL=

AI_PROVIDER=lanxin
AI_TIMEOUT_SECONDS=60
AI_ENABLE_MOCK=false
```

真实 `.env` 文件不得提交到 GitHub。

服务器上的 `.env` 由后端负责人维护。Android 端只知道 `PUBLIC_API_BASE_URL`，不能知道 `LANXIN_API_KEY`。

即使 GitHub 仓库是私有仓库，也禁止提交真实 `.env`。私有仓库仍然存在成员账号泄露、插件授权过大、Actions 日志外泄、后续误设公开、Git 历史难以清理等风险。团队协作应使用 `.env.example`、服务器统一配置、GitHub Secrets 或安全私下渠道分发密钥。具体规则见 `docs/密钥管理.md`。

### 4.4 后端代码原则

- 所有接口都必须有 Pydantic/SQLModel schema。
- 路由层只负责请求解析和响应返回，不直接写复杂业务逻辑。
- AI 调用只能写在 `services/ai`。
- 文件解析只能写在 `services/files`。
- 匹配算法只能写在 `services/matching`。
- 数据库模型统一写在 `db/models.py` 或按模块拆分。
- 禁止在接口函数里硬编码 API Key、prompt 长文本和数据库路径。
- 所有时间字段使用 ISO 8601 字符串或数据库 DateTime。
- 所有耗时任务必须可追踪状态，不能让 Android 端长时间无反馈等待。

## 5. API 规范

### 5.1 API 风格

本项目统一使用 REST API。

接口路径统一使用：

```txt
/api/v1/模块名
```

示例：

```txt
GET    /api/v1/health
POST   /api/v1/resumes/upload
POST   /api/v1/resumes/{resume_id}/parse
GET    /api/v1/tasks/{task_id}
POST   /api/v1/jobs/match
POST   /api/v1/interviews/mock/start
POST   /api/v1/interviews/mock/{session_id}/answer
POST   /api/v1/reviews/upload-audio
POST   /api/v1/reviews/{review_id}/analyze
GET    /api/v1/knowledge/items
```

### 5.2 统一响应格式

所有成功响应必须使用：

```json
{
  "success": true,
  "data": {},
  "error": null,
  "request_id": "req_20260602_001"
}
```

所有失败响应必须使用：

```json
{
  "success": false,
  "data": null,
  "error": {
    "code": "RESUME_FILE_TYPE_NOT_SUPPORTED",
    "message": "仅支持 PDF、DOC、DOCX、PNG、JPG 文件",
    "details": {}
  },
  "request_id": "req_20260602_001"
}
```

禁止不同接口各自返回 `msg`、`message`、`status`、`result`、`code` 等混乱结构。

### 5.3 同步任务和异步任务

短任务可以同步返回结果，例如：

- 健康检查。
- 查询列表。
- 保存用户编辑内容。
- 简单岗位匹配。

长任务必须使用异步任务模式，例如：

- 简历文件解析。
- 图片 OCR。
- 录音 ASR 转写。
- 面试复盘结构化分析。
- 大段简历优化。
- 多轮模拟面试总结。

异步任务流程：

```txt
Android 上传文件或提交任务
  -> 后端创建 task
  -> 后端立即返回 task_id
  -> Android 轮询 /api/v1/tasks/{task_id}
  -> 后端返回 pending / running / succeeded / failed
  -> Android 展示进度、结果或错误
```

创建任务响应示例：

```json
{
  "success": true,
  "data": {
    "task_id": "task_20260602_001",
    "status": "pending"
  },
  "error": null,
  "request_id": "req_20260602_001"
}
```

查询任务响应示例：

```json
{
  "success": true,
  "data": {
    "task_id": "task_20260602_001",
    "status": "running",
    "progress": 60,
    "message": "正在整理面试复盘结果",
    "result": null
  },
  "error": null,
  "request_id": "req_20260602_002"
}
```

任务状态统一使用：

```txt
pending
running
succeeded
failed
cancelled
```

Demo 阶段可以先使用数据库表记录任务状态，不强制上 Celery、Redis 或消息队列。如果任务执行很慢，可以先用 FastAPI `BackgroundTasks` 或简单线程池实现。等业务跑通后，再考虑专业任务队列。

### 5.4 错误码规范

错误码使用大写英文加下划线：

```txt
COMMON_BAD_REQUEST
COMMON_UNAUTHORIZED
COMMON_NOT_FOUND
COMMON_INTERNAL_ERROR

FILE_TOO_LARGE
FILE_TYPE_NOT_SUPPORTED
FILE_PARSE_FAILED

AI_PROVIDER_ERROR
AI_TIMEOUT
AI_INVALID_JSON

RESUME_NOT_FOUND
JOB_NOT_FOUND
REVIEW_NOT_FOUND
INTERVIEW_SESSION_NOT_FOUND
TASK_NOT_FOUND
TASK_FAILED
```

### 5.5 文件上传限制

Demo 阶段建议限制：

- 简历文件：PDF、DOC、DOCX、PNG、JPG。
- 录音文件：MP3、WAV、M4A、AAC。
- 单个简历最大：10 MB。
- 单个录音最大：50 MB。服务器只有 2 GiB 内存，不建议上传超大录音。
- 上传文件保存到 `uploads/`，数据库只存文件元数据和路径。
- 文件处理必须流式保存或分块读取，禁止一次性把大文件完整读入内存。

### 5.6 OpenAPI

FastAPI 自动生成：

```txt
http://127.0.0.1:8001/docs
http://127.0.0.1:8001/openapi.json
```

Android 端和 AI 编码助手应优先阅读 OpenAPI，而不是猜接口格式。

## 6. 数据库设计 v1

### 6.1 核心实体

Demo 阶段建议至少包含以下表：

```txt
users
tasks
resumes
resume_versions
jobs
job_matches
applications
interview_sessions
interview_answers
interview_reviews
knowledge_items
ai_call_logs
files
```

### 6.2 表职责

`users`：Demo 用户。可以先使用单用户，不做完整注册登录。

`tasks`：异步任务状态，例如简历解析、录音转写、面试复盘分析。

`resumes`：用户上传的原始简历和解析状态。

`resume_versions`：AI 优化后的简历版本。

`jobs`：岗位 JD 样例或用户导入的岗位。

`job_matches`：简历和岗位的匹配结果。

`applications`：投递进度，Demo 可以手动维护。

`interview_sessions`：模拟面试会话。

`interview_answers`：模拟面试中的问题、回答、评分。

`interview_reviews`：真实面试复盘记录。

`knowledge_items`：个人求职知识库条目，包括短板、面试问题、改进建议、岗位经验。

`ai_call_logs`：AI 调用日志，便于排查和复盘。

`files`：上传文件元数据。

### 6.3 知识库条目类型

`knowledge_items.type` 建议使用枚举：

```txt
interview_question
weakness
improvement_advice
resume_evidence
job_requirement
answer_template
company_note
```

### 6.4 是否需要向量数据库

复赛 Demo 第一阶段不强制上向量数据库。

可先用 SQLite 保存结构化知识条目，并通过关键词、标签、岗位方向、时间等字段检索。等主流程跑通后，再考虑增加轻量向量检索，例如 Chroma、FAISS 或服务端 embedding 检索。

不要一开始把 RAG 做成复杂系统。先确保“复盘结果能够保存，并在下一次模拟面试和简历优化中被读取使用”。

## 7. AI 服务规范

### 7.1 统一入口

后端必须提供统一 AI 服务接口，不允许在各模块散写蓝心 API 调用。

建议抽象：

```python
class AIService:
    def generate_text(self, task_name: str, messages: list, response_schema: dict | None = None) -> dict:
        ...

    def transcribe_audio(self, file_path: str) -> dict:
        ...

    def analyze_image(self, file_path: str, task_name: str) -> dict:
        ...

    def synthesize_speech(self, text: str) -> bytes:
        ...
```

业务模块只能调用 `AIService`，不能直接调用蓝心 SDK 或 HTTP 接口。

### 7.2 Prompt 管理

Prompt 必须放在：

```txt
apps/backend/app/services/ai/prompts/
```

每个 prompt 文件必须包含：

- 任务目标。
- 输入字段说明。
- 输出 JSON schema。
- 约束条件。
- 示例输入输出。
- 版本号。

示例文件：

```txt
resume_parse.md
resume_optimize.md
job_match.md
interview_review.md
mock_interview.md
answer_feedback.md
knowledge_extract.md
```

禁止把长 prompt 写死在路由函数里。

### 7.3 结构化输出优先

凡是要进入数据库或前端结构化展示的 AI 输出，都必须要求模型返回 JSON。

例如面试复盘输出：

```json
{
  "company_name": "示例科技",
  "job_title": "后端开发实习生",
  "interview_round": "技术一面",
  "questions": [
    {
      "question": "请介绍你的项目架构",
      "answer_summary": "用户介绍了 FastAPI 后端和简历解析流程",
      "issue": "缺少数据库设计和异常处理说明",
      "improvement": "补充表结构、错误处理和接口稳定性说明"
    }
  ],
  "weaknesses": [
    {
      "name": "项目架构表达不完整",
      "evidence": "回答中只讲了功能，没有讲模块边界",
      "priority": "high"
    }
  ],
  "next_actions": [
    "准备 1 分钟项目架构介绍",
    "补充数据库表设计表达"
  ]
}
```

### 7.4 AI 调用日志

每次 AI 调用至少记录：

- `task_name`
- `provider`
- `model`
- `input_summary`
- `output_summary`
- `status`
- `latency_ms`
- `error_message`
- `created_at`

不要把完整隐私材料明文写入日志。可以保存摘要和调试 ID。

### 7.5 Mock 模式

必须支持 AI Mock 模式：

```txt
AI_ENABLE_MOCK=true
```

Mock 模式用于：

- API Key 未配置时继续开发 UI。
- 比赛现场网络不稳定时演示主流程。
- 蓝心接口额度不足时保底。

Mock 返回必须接近真实结构，不允许只返回一句“测试成功”。

## 9. 核心业务流程

### 9.1 简历优化流程

```txt
上传简历
  -> 保存文件
  -> 提取文本
  -> AI 解析为结构化档案
  -> 用户确认或编辑
  -> AI 生成优化建议
  -> 保存简历版本
```

必须保存：

- 原始文件。
- 提取文本。
- 结构化档案。
- 优化建议。
- 优化后版本。

### 9.2 岗位匹配流程

```txt
选择简历
  -> 导入岗位 JD
  -> AI 提取岗位要求
  -> 匹配简历能力证据
  -> 输出匹配分数、优势、差距、准备建议
  -> 保存匹配记录
```

岗位匹配结果应至少包含：

- 总匹配度。
- 技能匹配。
- 项目经历匹配。
- 学历/专业要求匹配。
- 风险点。
- 面试准备建议。

### 9.3 模拟面试流程

```txt
选择目标岗位
  -> 选择面试类型
  -> 读取简历、JD、历史复盘短板
  -> AI 生成问题
  -> 用户文字或语音回答
  -> ASR 转写
  -> AI 评分与反馈
  -> 保存会话
```

面试类型建议：

- 技术面。
- 项目深挖面。
- HR 面。
- 行为面试。
- 压力面试。
- 国企结构化面试。

### 9.4 面试复盘流程

```txt
上传录音或输入复盘
  -> ASR 转写
  -> AI 清洗和归纳
  -> 提取问题、回答、反馈、短板、建议
  -> 用户确认
  -> 保存复盘记录
  -> 抽取知识库条目
  -> 同步至模拟面试和简历优化
```

复盘模块是本产品的核心差异化功能，优先级最高。

## 12. 演示和部署规范

### 12.1 云服务器默认演示方案

复赛 Demo 默认使用云服务器后端。Android App 请求云服务器 API，云服务器负责调用蓝心大模型、解析文件、读写数据库并返回结果。

默认链路：

```txt
Android APK
  -> https://api.你的域名.com 或 http://服务器公网IP:8001
  -> FastAPI
  -> SQLite / uploads
  -> 蓝心大模型 API
  -> FastAPI 返回结构化结果
  -> Android 展示
```

服务器配置：

```txt
2 vCPU
2 GiB 内存
40 GiB ESSD 云盘
```

服务器部署原则：

- 不在服务器本地部署大模型。
- 不在服务器本地跑大型 ASR 模型。
- 蓝心 API Key 只保存在服务器 `.env`。
- 上传文件限制大小，并定期清理。
- SQLite 数据库和 `uploads/` 要备份。
- 正式演示前尽量配置域名和 HTTPS。

### 12.2 服务器部署检查清单

后端部署前检查：

- Python 环境可用。
- FastAPI 依赖安装完成。
- `.env` 已配置，且包含蓝心 API Key。
- `data/` 和 `uploads/` 目录存在。
- SQLite 数据库可创建和写入。
- 服务器安全组已开放后端端口，建议 `8001` 或经 Nginx 转发到 `443`。
- `/api/v1/health` 可从手机网络访问。
- `/docs` 可访问，正式提交前可考虑关闭或加保护。
- Android APK 中 API 地址指向云服务器。

最小启动命令：

```powershell
cd apps/backend
uvicorn app.main:app --host 0.0.0.0 --port 8001
```

正式部署建议：

```txt
Nginx 443/HTTPS
  -> 127.0.0.1:8001 FastAPI
```

进程管理可选：

- systemd。
- Supervisor。
- Docker Compose。
- 云服务器面板自带进程守护。

### 12.3 本地真机调试

本地真机调试只用于开发阶段，不作为复赛正式演示主方案。

1. 电脑和手机连接同一个 Wi-Fi。

比赛现场必须准备兜底：

## 17. v1 强制约束摘要

所有成员和 AI 必须遵守：

- 项目主线是“面试复盘驱动的个人求职知识库”。
- 移动端主路线是 Android Studio + Kotlin + Jetpack Compose。
- Stitch/Figma 是设计和原型工具，不是最终 APK 工程。
- 后端主路线是 Python FastAPI。
- 后端默认部署在云服务器，手机 App 请求服务器 API。
- 手机 App 只负责交互、录音、文件选择和结果展示。
- 文档解析、模型调用、Prompt 编排和数据库读写都放在服务器后端。
- 数据库 Demo 阶段使用服务器上的 SQLite。
- AI 供应商主路线是蓝心大模型。
- 蓝心 API Key 只能放服务器 `.env`，禁止进入 APK。
- AI 调用必须统一封装，禁止散落直连。
- API 必须使用统一响应格式。
- 长任务必须支持 `task_id` 和状态查询。
- 接口必须有 OpenAPI 文档。
- 真实密钥、真实简历、真实录音不得提交。
- 复赛优先打磨简历、岗位、模拟面试、面试复盘这条闭环。
