## 3. 主要冲突与解决方式

### 3.1 用户注册与档案默认画像

涉及文件：

- `ai-job-backend/src/auth/auth.service.ts`
- `ai-job-backend/src/profile/profile.service.ts`
- `ai-job-backend/src/profile/dto/update-profile.dto.ts`
- `frontEnd/src/components/ProfileView.tsx`

冲突/差异：

- zpq 侧把档案页从旧的泛方向标签，例如 `internet`、`ai`、`tech`，改为职位类别和岗位方向。
- ps 侧也修改了用户、档案相关逻辑，双方都碰到了 `auth.service.ts` 和 `profile.service.ts`。

解决方式：

- 保留现有 `UserProfile` 表，不新增表。
- 后端默认画像统一改为：
  - `targetDirection = "研发"`
  - `targetDirections = ["研发", "后端"]`
- 前端增加旧值兼容映射：
  - `internet -> 研发`
  - `ai -> 研发 / 算法 / 自然语言处理 / 机器学习`
  - `finance -> 产品 / 数据分析`
  - `tech -> 研发 / 后端`
- `customTargetDirection` 改为“目标岗位关键词”，最多 160 字。
- 岗位推荐优先级明确为：
  - 本次岗位推荐输入最高。
  - 档案页目标岗位关键词第二。
  - 档案页职位类别/岗位方向仅作为兜底画像。

涉及文件：

  - `Job.notes`
  - `Job.priority`

- 运行时如果出现 `column does not exist`，说明代码已更新但数据库迁移未执行，需要执行：


## 4. 数据库最终结构变化

本次集成后数据库结构相对主线主要新增：

| 表 | 字段 | 类型 | 来源 | 用途 |
| --- | --- | --- | --- | --- |
| `Job` | `salary` | `TEXT` | zpq | 投递管理薪资展示 |
| `Job` | `location` | `TEXT` | zpq | 投递管理城市/地点 |
| `Job` | `notes` | `TEXT` | zpq | 投递备注 |
| `Job` | `priority` | `TEXT DEFAULT 'normal'` | zpq | 投递优先级 |
| `InterviewSession` | `strategySnapshot` | `JSONB` | ps | 面试策略快照 |
| `ReviewReport` | `generatedBy` | `TEXT DEFAULT 'ai'` | ps | 报告生成来源 |
| `ReviewReport` | `advantageSummary` | `JSONB` | ps | 优势复盘 |
| `ReviewReport` | `weaknessSummary` | `JSONB` | ps | 短板复盘 |
| `ReviewReport` | `interviewerSteeringReview` | `JSONB` | ps | 面试引导复盘 |
| `Resume` | `jdMatchResult` | `JSONB` | ps | 简历与 JD 匹配分析结果 |

数据库处理结论：

- 不新建单独的“投递记录表”，一期继续复用 `Job` 表承载岗位和投递状态。
- 不新建单独的“职位类别表”，档案页求职偏好继续存入 `UserProfile` 现有字段。
- 新增 JSON 字段均允许为空，降低对历史数据的影响。
- `generatedBy` 和 `priority` 使用默认值，避免历史行违反非空约束。
