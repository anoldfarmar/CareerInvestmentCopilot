# 当前后端数据库说明

本文档对应当前后端目录：

```text
ai-job-backend
```

当前后端连接的是 `.env` 中的 `DATABASE_URL`。本地环境目前指向 PostgreSQL：

```text
localhost:5433 / zhitou_copilot / public schema
```

## 1. 当前状态总览

当前项目处在一次数据库模型迁移过程中，需要特别区分两套表名：

| 类型 | 表名示例 | 当前状态 |
| --- | --- | --- |
| 旧库蛇形表 | `users`、`user_profiles`、`job_descriptions`、`job_matches`、`knowledge_chunks` | 旧设计/旧数据库命名 |
| 当前 Prisma 新表 | `"User"`、`"UserProfile"`、`"Job"`、`"Resume"`、`"InterviewSession"` | 当前多数后端 service 正在使用 |

目前已经做过一次兼容调整：

```text
注册 / 登录 -> users
```

也就是说，登录页注册用户时，用户会进入旧表：

```text
users
```

但当前多数业务模块仍按当前 Prisma schema 访问新表，例如：

```text
Resume
Job
InterviewKnowledgeBase
RealInterviewRecord
InterviewSession
ReviewReport
```

因此，如果要完全回到旧库体系，还需要继续把岗位、简历、复盘、知识库等 service 迁移到旧表。

## 2. 当前主要表

### 2.1 用户登录表：users

当前认证链路使用 Prisma 模型：

```text
LegacyUser -> users
```

主要字段：

| 字段 | 说明 |
| --- | --- |
| `id` | 用户 ID，字符串，默认 `cuid()` |
| `email` | 邮箱，唯一 |
| `phone` | 手机号，唯一，可为空 |
| `name` | 用户名 |
| `avatar_url` | 头像 URL |
| `role` | 角色，默认 `user` |
| `status` | 用户状态，默认 `active` |
| `password_hash` | bcrypt 后的密码哈希 |
| `created_at` | 创建时间 |
| `updated_at` | 更新时间 |

对应接口：

| 前端动作 | 后端接口 | 写入/读取 |
| --- | --- | --- |
| 注册 | `POST /auth/register` | 查询并写入 `users` |
| 登录 | `POST /auth/login` | 查询 `users`，校验 `password_hash` |
| 查询当前用户 | `GET /auth/me` | JWT 解码后查询 `users` |

说明：

```text
注册会创建 users 记录。
登录不会创建用户，只会校验已有 users 记录并返回 JWT。
```

### 2.2 新版用户表："User"

当前数据库中也存在 Prisma 新表：

```text
"User"
```

这是当前多数业务表的外键来源，例如 `"Resume"."userId"`、`"Job"."userId"`。

目前认证已经切到 `users`，所以 `"User"` 暂时不再作为登录主表。后续需要二选一：

```text
方案 A：全项目继续使用 "User" / "Resume" / "Job" 这套新表。
方案 B：全项目迁回 users / resumes / job_descriptions 这套旧表。
```

当前你希望走方案 B，所以后续需要继续迁移业务 service。

## 3. 用户输入数据如何存储

### 3.1 注册 / 登录

流程：

```text
前端登录页
  -> POST /auth/register 或 POST /auth/login
  -> AuthService
  -> users
```

注册时：

```text
email        -> users.email
name         -> users.name
password     -> bcrypt hash -> users.password_hash
role/status  -> 默认 user / active
```

登录时：

```text
email/password
  -> 查询 users.email
  -> bcrypt compare password_hash
  -> 返回 JWT
```

JWT 中的 `sub` 当前保存的是：

```text
users.id
```

### 3.2 简历创建、解析、结构化、优化

当前多数简历接口仍使用新表：

```text
"Resume"
"ResumeVersion"
"ResumeExport"
```

主要接口：

| 动作 | 接口 | 当前落表 |
| --- | --- | --- |
| 创建简历 | `POST /resumes` | `"Resume"` |
| 查询简历列表 | `GET /resumes` | `"Resume"` |
| 上传文件解析 | `POST /resumes/:id/parse/upload` | 更新 `"Resume"."mineruTaskId"`、`"parseStatus"` |
| 查询解析结果 | `GET /resumes/:id/parse` | 更新 `"Resume"."originalContent"` |
| AI 结构化 | `POST /resumes/:id/structure` | 更新 `"Resume"."structuredContent"` |
| AI 优化 | `POST /resumes/:id/optimize` | 更新 `"Resume"."optimizedContent"`、`"draftContent"` |
| 保存结构化内容 | `PUT /resumes/:id/structured-content` | 更新 `"Resume"."structuredContent"` |
| 保存优化稿 | `PUT /resumes/:id/optimized-content` | 写 `"ResumeVersion"`，更新 `"Resume"` |
| 定稿 | `POST /resumes/:id/finalize` | 写 `"ResumeVersion"`，更新 `"Resume"."finalizedContent"` |
| 导出 PDF | `POST /resumes/:id/export/pdf` | 写 `"ResumeExport"`，PDF 文件落 `storage/resume-exports` |

字段含义：

| 表/字段 | 说明 |
| --- | --- |
| `"Resume"."originalContent"` | MinerU 解析后的 Markdown 或原始文本 |
| `"Resume"."structuredContent"` | DeepSeek 结构化后的简历 JSON |
| `"Resume"."optimizedContent"` | DeepSeek 优化后的简历 JSON |
| `"Resume"."draftContent"` | 前端编辑中的优化稿草稿 |
| `"Resume"."finalizedContent"` | 确认后的最终版 |
| `"ResumeVersion"."content"` | 每次保存/定稿的历史版本 |
| `"ResumeExport"."filePath"` | 导出的 PDF 本地路径 |

旧库预期表：

```text
resumes
```

旧表字段规划中，类似内容应存：

```text
resumes.raw_text
resumes.structured_profile
resumes.optimization_advice
```

但当前 service 尚未完全迁回旧表。

## 4. 录音导入、转文字、构建知识库

这是你最关心的数据流。当前后端有两条录音/ASR 链路。

### 4.1 临时语音转文字

接口：

```text
POST /speech/transcribe
```

用途：

```text
用于模拟面试语音回答的临时转写。
```

流程：

```text
前端上传 audio 文件或 audioUrl
  -> SpeechService
  -> 如果是本地文件，保存到 storage/asr-audios
  -> AsrService 调 DashScope Fun-ASR
  -> 返回 text / speakerTranscript / roleTranscript
```

当前是否入库：

```text
不入库。
```

本地文件保存位置：

```text
storage/asr-audios
```

返回字段：

| 字段 | 说明 |
| --- | --- |
| `text` | 优先使用角色转写文本，否则使用普通全文 |
| `provider` | 当前为 `dashscope` |
| `model` | 默认 `fun-asr` |
| `speakerTranscript` | 按 speaker 分段的文本 |
| `roleTranscript` | 面试官/候选人角色格式文本 |

### 4.2 真实面试知识库录音

相关表：

```text
"InterviewKnowledgeBase"
```

接口：


```text

```


#### 第三步：录音转文字

接口：

```text

```

```text

  -> 轮询任务完成
  -> 下载 ASR JSON
```

更新字段：

| 表/字段 | 说明 |
| --- | --- |

| `"RealInterviewRecord"."asrProvider"` | ASR 供应商，当前 `dashscope` |

| `"RealInterviewRecord"."asrRawJson"` | ASR 原始 JSON |
| `"RealInterviewRecord"."speakerTranscript"` | speaker 分离文本 |
| `"RealInterviewRecord"."roleTranscript"` | 面试官/候选人角色文本 |
| `"RealInterviewRecord"."transcribedAt"` | 转写完成时间 |
| `"RealInterviewRecord"."status"` | 成功后 `ready`，失败后 `failed` |
| `"RealInterviewRecord"."buildStatus"` | 有文本则 `not_built`，无文本则 `empty` |
| `"RealInterviewRecord"."buildError"` | 失败原因 |

#### 第四步：文字梳理为知识库

接口：

```text

```


当前 `chunks` 不是单独表，而是存在：


## 5. 当前 RAG / 向量数据库情况

### 5.1 当前代码实际使用的检索方式

当前 `InterviewRagService` 没有查询 pgvector 表。

它的逻辑是：

```text
读取 RealInterviewRecord.chunks JSON
  -> 对 query 生成本地 hash embedding
  -> 对 chunk 文本生成本地 hash embedding
  -> 在内存中计算 cosine similarity
  -> 取 TopK
```

相关代码：

```text
src/interviews/interview-rag.service.ts
src/common/ai/local-embedding.util.ts
```

所以当前运行代码中的“RAG”更准确地说是：

```text
JSON chunks + 本地 hash 向量 + 内存相似度排序
```

### 5.2 当前哪张表是向量数据库？

按当前 `ai-job-backend/prisma/schema.prisma`：

```text
没有真正的向量表。
```

当前 schema 中没有：

```text
knowledge_chunks
embedding vector
```

也没有 Prisma 字段：

```text
Unsupported("vector")
```

### 5.3 旧规划中的向量表

旧文档中设计过：

```text
knowledge_chunks
```

它原本用于：

```text
chunk_text      -> 可检索文本片段
embedding       -> pgvector 向量字段
embedding_model -> embedding 模型名
source_type     -> 来源类型
source_id       -> 来源业务 ID
user_id         -> 用户隔离
status          -> active / archived
```

但当前这张表不在当前 Prisma schema 里。若要恢复正式 pgvector 检索，需要重新补：

```text
CREATE EXTENSION IF NOT EXISTS vector;
knowledge_items
knowledge_chunks
knowledge_chunks.embedding vector(n)
```

然后把 `"RealInterviewRecord"."chunks"` 中的 JSON 片段同步/切分到 `knowledge_chunks`。

## 6. 当前数据流图

### 6.1 注册登录

```text
LoginView
  -> /auth/register
  -> users
  -> 返回 JWT
  -> localStorage.career-investment-token
```

```text

  -> Resume

  -> MinerU
  -> Resume.mineruTaskId / parseStatus

  -> Resume.originalContent

AI 结构化
  -> DeepSeek
  -> Resume.structuredContent

  -> DeepSeek

保存版本
  -> ResumeVersion

导出 PDF
  -> storage/resume-exports
```

### 6.3 岗位链路

```text
创建/保存 JD
  -> Job.description

更新投递状态
  -> Job.status

  -> 聚合 Job.status
```

### 6.4 真实面试录音到知识库

```text
创建知识库
  -> InterviewKnowledgeBase

上传录音
  -> storage/knowledge-audios
  -> RealInterviewRecord.audioUrl / audioFileName / audioFileSize

录音转文字
  -> DashScope Fun-ASR
  -> RealInterviewRecord.asrRawJson
  -> RealInterviewRecord.speakerTranscript
  -> RealInterviewRecord.roleTranscript
  -> RealInterviewRecord.transcript

构建知识库记录
  -> DeepSeek
  -> RealInterviewRecord.structuredContent
  -> RealInterviewRecord.chunks
```

### 6.5 知识库用于模拟面试

```text
创建模拟面试
  -> 传入 knowledgeBaseIds
  -> 查询 RealInterviewRecord
  -> 读取 transcript / chunks
  -> InterviewRagService 内存 TopK
  -> 生成面试题
  -> InterviewSession.questions
  -> InterviewSession.messages
```

### 6.6 模拟面试到复盘报告

```text
用户回答
  -> InterviewSession.messages

结束面试
  -> ReportsService.generate
  -> DeepSeek 或本地规则
  -> ReviewReport
```

## 8. 后续迁移建议

如果目标是“完全使用旧表 users / user_profiles / resumes / job_descriptions / job_matches / knowledge_chunks”，建议按顺序迁移：

1. 认证：已完成，注册/登录走 `users`。
2. 用户画像：把 `UserProfile` 迁到 `user_profiles`。
3. 简历：把 `"Resume"` 迁到 `resumes`，字段映射 `originalContent -> raw_text`、`structuredContent -> structured_profile`。
4. 岗位：把 `"Job"` 迁到 `job_descriptions`，把匹配结果持久化到 `job_matches`。
