# 数据库说明文档

本文档用于说明职投 Copilot 当前数据库在哪里、怎么查看、各张表分别存什么、ASR 面试复盘知识库数据如何从文件进入数据库，以及哪些表是模拟面试和 RAG 检索真正会读取的。

## 1. 当前数据库在哪里

当前项目使用：

```text
PostgreSQL + pgvector
```

不是 SQLite，也不是项目目录里的某个 `.db` 文件。

当前数据库配置：

```text
数据库服务：PostgreSQL
数据库名称：zhitou_copilot
数据库用户：zhitou_app
数据库地址：127.0.0.1:5432
向量扩展：pgvector
后端连接配置：/home/CareerInvestmentCopilot/apps/backend/.env
Prisma schema：/home/CareerInvestmentCopilot/apps/backend/prisma/schema.prisma
数据库 migration：/home/CareerInvestmentCopilot/apps/backend/prisma/migrations/
```

后端通过 `.env` 中的 `DATABASE_URL` 连接数据库：

```text
DATABASE_URL=postgresql://...
```

`.env` 里包含真实数据库密码，不允许提交到 Git。

## 2. 数据库和项目文件的关系

项目里有三类数据位置：

```text
apps/backend/data/
  -> ASR 转写结果、AI 复盘 JSON、prompt、测试输出等中间产物

apps/backend/uploads/ 或 public 临时目录
  -> 上传文件、音频文件、临时公网访问文件

PostgreSQL: zhitou_copilot
  -> 用户、文件元数据、面试复盘、知识库、向量、模拟面试消息等正式业务数据
```

原则：

```text
音频、PDF、Markdown 大文件：放文件系统或对象存储
文件路径、文件大小、hash、业务状态：进数据库
转写文本、复盘结构化结果、知识块、向量：进数据库
```

不要把音频二进制直接塞进数据库。

## 3. 推荐可视化工具

### 3.1 Prisma Studio

适合快速查看当前项目数据。

服务器执行：

```bash
cd /home/CareerInvestmentCopilot/apps/backend
pnpm prisma studio --hostname 127.0.0.1 --port 5555
```

Windows 本机通过 SSH 隧道访问：

```bash
ssh -L 5555:127.0.0.1:5555 root@服务器公网IP
```

浏览器打开：

```text
http://127.0.0.1:5555
```

安全要求：

```text
推荐：--hostname 127.0.0.1
禁止：--hostname 0.0.0.0
```

`127.0.0.1` 只允许服务器本机访问，再通过 SSH 隧道给自己看；`0.0.0.0` 可能暴露到公网，不安全。

### 3.2 DBeaver

适合长期开发使用。Windows 安装 DBeaver 后，通过 SSH Tunnel 连接服务器 PostgreSQL。

数据库连接信息：

```text
Database Type：PostgreSQL
Host：127.0.0.1
Port：5432
Database：zhitou_copilot
Username：zhitou_app
Password：查看服务器 .env 或 .postgres_password
```

如果从 Windows 连接服务器，建议使用 DBeaver 自带 SSH Tunnel，不要直接把 PostgreSQL 5432 端口暴露公网。

### 3.3 psql

适合调试，不适合日常看数据。

```bash
sudo -u postgres psql -d zhitou_copilot
```

常用命令：

```sql
\dt
\d knowledge_chunks
SELECT id, user_id, embedding_model, left(chunk_text, 80) FROM knowledge_chunks LIMIT 5;
\q
```

## 5. 数据库业务分区

### 5.1 用户基础数据

```text
users
user_profiles
files
```

作用：

```text
users：记录用户账号、名称、状态
user_profiles：记录用户学校、专业、目标岗位、技能、城市等画像
files：记录用户上传或系统生成的文件元数据
```

文件表只保存路径和元数据，不保存文件二进制。

### 5.2 面试复盘数据

```text
interview_reviews
review_audios
review_transcripts
review_qa_pairs
review_insights
```

作用：

```text
interview_reviews：一次面试复盘的主记录
review_audios：该次复盘对应的音频文件
review_transcripts：ASR 原文、清洗文本、角色文本
review_qa_pairs：面试官问题、用户回答、得分、短板、建议
review_insights：AI 总结出的亮点、问题、短板、行动建议
```

这部分是“面试复盘历史”。它可以被前端直接展示，也可以被抽取成知识库。

### 5.3 知识库数据

```text
knowledge_items
knowledge_chunks
```

这两张是个性化 RAG 的核心。

```text
knowledge_items：业务层知识条目，适合人看
knowledge_chunks：检索层知识块，适合 RAG 查
```

简单理解：

```text
KnowledgeItem = 一条知识卡片
KnowledgeChunk = 可以被 embedding 和 pgvector 检索的一段文本
```

模拟面试真正做语义召回时，主要读取：

```text
knowledge_chunks
```

重点字段：

| 字段 | 说明 |
| --- | --- |
| id | 知识块 ID |
| user_id | 属于哪个用户 |
| knowledge_item_id | 来自哪个知识条目 |
| source_type | 来源类型，例如 review_insight、review_qa、resume、job |
| source_id | 来源记录 ID |
| chunk_text | 可被检索的文本内容 |
| embedding | pgvector 向量字段 |
| embedding_model | 生成向量使用的模型，例如 vivo:m3e-base |
| tags_json | 标签 JSON |
| token_count | 文本长度或 token 数估算 |
| status | active、archived 等状态 |
| created_at | 创建时间 |

当前正式 RAG 检索应该优先确认：

```text
knowledge_chunks.embedding 不为空
knowledge_chunks.embedding_model = vivo:m3e-base
knowledge_chunks.status = active
```

如果 `embedding_model` 是 `local-hash-256`，说明这条还是本地测试向量，不是正式语义 embedding。

### 5.4 简历和岗位数据

```text
resumes
job_descriptions
job_matches
```

作用：

```text
resumes：用户简历原文、结构化简历、优化建议
job_descriptions：岗位 JD 原文、结构化要求、来源链接
job_matches：简历和岗位的匹配分数、优势、差距、准备建议
```

后续模拟面试应该综合读取：

```text
resume + job + knowledge_chunks + historical qa
```

也就是：

```text
resumes
job_descriptions
knowledge_chunks
review_qa_pairs
review_insights
```

### 5.5 模拟面试数据

```text
mock_interview_sessions
mock_interview_messages
```

作用：

```text
mock_interview_sessions：一次模拟面试会话
mock_interview_messages：会话中的 system、assistant、user 消息
```

例如你在 Prisma Studio 里看到 `MockInterviewMessage` 有 2 条，说明之前生成模拟面试 prompt / 问题时，已经写入了一次系统消息和一次助手消息。

这不是知识库本体，而是模拟面试过程记录。

### 5.6 任务和 AI 调用日志

```text
tasks
ai_call_logs
```

作用：

```text
tasks：记录长任务进度，例如 ASR 转写、复盘生成、embedding 批处理
ai_call_logs：记录模型供应商、模型名、用途、状态、耗时、错误信息
```

Demo 阶段可以先少量使用。后续如果要做稳定后台任务，应让 ASR、AI 复盘、embedding 都创建任务记录。

## 6. ASR 面试复盘进入数据库的流程

整体链路：

```text
音频文件
  -> ASR 转写
  -> 清洗转写文本
  -> AI 面试复盘
  -> 导入 PostgreSQL
  -> 生成 knowledge_items
  -> 生成 knowledge_chunks
  -> embedding 写入 pgvector
  -> 模拟面试 RAG 检索
```

对应命令：

```bash
cd /home/CareerInvestmentCopilot/apps/backend
pnpm asr:transcribe -- --name 腾讯音乐_数据科学 --audio-url "http://公网IP/asr-audio/随机目录/xxx.m4a"
pnpm review:ai -- --name 腾讯音乐_数据科学
pnpm review:import -- --name 腾讯音乐_数据科学 --user-id demo_user
pnpm knowledge:embed -- --user-id demo_user --provider vivo --model m3e-base --replace
```

每一步写入或产生的数据：

| 步骤 | 产物 |
| --- | --- |
| ASR 转写 | `data/asr_results/*_asr.json`、`*_transcript.txt` |
| AI 复盘 | `*_ai_review.json`、`*_clean_transcript.txt` |
| 导入数据库 | `interview_reviews`、`review_transcripts`、`review_qa_pairs`、`review_insights`、`knowledge_items`、`knowledge_chunks` |
| embedding | 更新 `knowledge_chunks.embedding` 和 `knowledge_chunks.embedding_model` |
| RAG 检索 | 从 `knowledge_chunks` TopK 召回 |
| 模拟面试 | 写入 `mock_interview_sessions`、`mock_interview_messages` |

## 7. 模拟面试如何读取数据库

输入目标：

```text
腾讯音乐 数据科学 推荐系统
```

后端应该执行：

```text
1. 把目标 query 转成 embedding
2. 在 knowledge_chunks 里按 user_id 过滤当前用户
3. 用 pgvector 找最相似的 TopK chunks
4. 补充读取用户简历、岗位 JD、历史问答和复盘洞察
5. 拼接成模拟面试官 prompt
6. 生成问题或进入多轮对话
```

当前测试命令：

```bash
pnpm rag:retrieve -- --user-id demo_user --query "腾讯音乐 数据科学 推荐系统" --top-k 8 --model vivo:m3e-base
pnpm mock:build-context -- --user-id demo_user --target "腾讯音乐 数据科学 推荐系统"
pnpm mock:generate-questions -- --user-id demo_user --target "腾讯音乐 数据科学 推荐系统"
```

核心读取表：

```text
users
resumes
job_descriptions
review_qa_pairs
review_insights
knowledge_chunks
```

核心写入表：

```text
mock_interview_sessions
mock_interview_messages
```

## 8. 常用检查 SQL

查看表：

```sql
\dt
```

查看知识块数量：

```sql
SELECT count(*) FROM knowledge_chunks;
```

查看每种 embedding 模型的数量：

```sql
SELECT embedding_model, count(*)::int
FROM knowledge_chunks
GROUP BY embedding_model
ORDER BY embedding_model;
```

查看还没有向量的知识块：

```sql
SELECT id, left(chunk_text, 120) AS preview
FROM knowledge_chunks
WHERE embedding IS NULL
LIMIT 20;
```

查看最近一次面试复盘：

```sql
SELECT id, user_id, company_name, position_name, status, created_at
FROM interview_reviews
ORDER BY created_at DESC
LIMIT 5;
```

查看某次复盘的问答：

```sql
SELECT order_no, question, answer_summary, score
FROM review_qa_pairs
WHERE review_id = '替换为 interview_reviews.id'
ORDER BY order_no;
```

查看 RAG 知识块预览：

```sql
SELECT id, user_id, embedding_model, source_type, left(chunk_text, 120) AS preview
FROM knowledge_chunks
WHERE status = 'active'
ORDER BY created_at DESC
LIMIT 10;
```

## 9. 当前开发注意事项

1. 不要手动改数据库结构。

数据库结构变更应该改：

```text
apps/backend/prisma/schema.prisma
```

然后通过 Prisma migration 管理。

2. 不要提交真实数据库密码。

这些文件不能提交 Git：

```text
apps/backend/.env
apps/backend/.postgres_password
```

3. 不要把 PostgreSQL 5432 端口直接开放公网。

本机查看数据库建议走：

```text
SSH Tunnel + Prisma Studio / DBeaver
```

4. 不要把音频二进制直接存数据库。

数据库只保存：

```text
storage_path
public_url
mime_type
size_bytes
sha256
```

5. RAG 正式检索看 `knowledge_chunks`，不是看 `knowledge_items`。

```text
knowledge_items：适合人理解和管理
knowledge_chunks：适合模型检索和召回
```

6. pgvector 字段在 Prisma 里是 `Unsupported("vector")`。

普通 CRUD 可以用 Prisma Client；向量相似度查询建议使用 raw SQL。

## 10. 新人查看顺序

如果第一次打开 Prisma Studio，建议按这个顺序看：

```text
1. User
2. InterviewReview
3. ReviewTranscript
4. ReviewQaPair
5. ReviewInsight
6. KnowledgeItem
7. KnowledgeChunk
8. MockInterviewSession
9. MockInterviewMessage
```

不要一开始就看所有表。先理解一条音频复盘如何变成知识块，再看模拟面试如何读取这些知识块。

最重要的判断标准：

```text
KnowledgeChunk 里有 chunkText
KnowledgeChunk 里有 embedding
KnowledgeChunk 的 embeddingModel 是正式模型
模拟面试能从 KnowledgeChunk 召回相关内容
```

这条链路跑通后，数据库就不只是“存数据”，而是在支撑个性化模拟面试官。
