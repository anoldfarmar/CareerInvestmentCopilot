下面这套规则可以理解成一个**“AI 简历粗筛评分器”**：不是简单关键词匹配，而是把 JD 拆成要求，再用**硬规则 + 字段匹配 + embedding 相似度 + 大模型语义判断**综合评估。核心目标是：**宁可保守，不要把明显不匹配的人放进面试池；但也不要因为候选人没写同义词而误杀。**

---

# 一、整体筛选流程

```text
输入：简历 Resume + 岗位 JD

Step 1：解析 JD
  - 提取岗位名称、级别、必备条件、加分项、职责、技能栈、经验年限、学历、行业背景等

Step 2：解析简历
  - 提取教育、工作经历、项目经历、技能、证书、论文/竞赛、成果指标等

Step 3：标准化
  - 技能同义词归一
  - 年限归一
  - 学历归一
  - 岗位级别归一
  - 项目/行业领域归一

Step 4：硬性条件筛选
  - 必备条件不满足，直接淘汰或降级

Step 5：多维度匹配评分
  - 必备条件匹配
  - 技能匹配
  - 项目/工作经验匹配
  - 行业背景匹配
  - 职责匹配
  - 教育/证书匹配
  - 成果质量匹配
  - 稳定性/连续性风险

Step 6：输出结果
  - 总分
  - 推荐等级
  - 匹配证据
  - 不匹配原因
  - 风险点
  - 是否建议进入人工复核
```

# 四、核心评分维度设计

总分建议为 **100 分制**。

| 维度        | 权重 | 说明                         |
| --------- | -: | -------------------------- |
| 必备条件匹配    | 35 | JD 中明确写“必须、要求、需要、具备”的内容    |
| 技能栈匹配     | 20 | 编程语言、框架、工具、算法方法            |
| 项目/工作经验匹配 | 20 | 是否做过类似任务，是否有真实业务/科研项目      |
| 岗位职责匹配    | 10 | 简历经历是否覆盖 JD 工作内容           |
| 行业/场景匹配   |  5 | 是否有相关行业背景，如电力、无人机、自动驾驶、医疗等 |
| 教育背景/证书   |  5 | 学历、专业、证书、语言等               |
| 成果质量      |  5 | 论文、竞赛、专利、指标提升、落地成果         |

# 五、硬性淘汰规则

这部分仿照大厂粗筛逻辑，优先处理“明显不符合”的情况。

## 1. 必备条件直接淘汰

例如 JD 写：

> 必须具备 3 年以上 Java 后端开发经验。

简历中完全没有 Java 后端经验，则直接标记：

```json
{
  "decision": "reject",
  "reason": "缺少核心必备条件：3 年以上 Java 后端开发经验"
}
```

## 2. 最低学历不满足

例如 JD 写：

> 本科及以上学历。

简历最高学历是大专，可以直接淘汰，除非 JD 明确写“能力优秀者可放宽”。

## 3. 核心技能缺失

例如算法岗 JD 写：

> 熟练掌握 Python 和 PyTorch。

简历只有 MATLAB，没有 Python/PyTorch 项目证据，则强烈降权或淘汰。

## 4. 岗位方向严重不符

例如 JD 是：

> 计算机视觉算法工程师。

简历主要是：

> Java 后端、测试、运维，无任何视觉/算法项目。

则即使学历不错，也应低分。

## 5. 年限严重不符

例如 JD 要：

> 5 年以上推荐系统经验。

候选人是应届生，即使项目相关，也不能直接视为满足。

可以输出：

```json
{
  "hard_filter_pass": false,
  "reason": "工作年限不满足：JD 要求 5 年以上，简历显示为应届生"
}
```

# 六、技能匹配规则

技能不能只做关键词匹配，要分成几个层级。

## 1. 技能证据等级

| 等级 | 含义        | 示例                       |
| -- | --------- | ------------------------ |
| L0 | 未出现       | 简历没有提到 PyTorch           |
| L1 | 仅关键词出现    | 技能栏写了 PyTorch，但没有项目证据    |
| L2 | 项目中使用过    | 项目描述中提到使用 PyTorch        |
| L3 | 工作/实习中使用过 | 实习中负责 PyTorch 模型训练       |
| L4 | 有结果指标     | 使用 PyTorch 模型使 mAP 提升 5% |
| L5 | 深度掌握/主导优化 | 主导模型结构改进、部署、加速、压缩        |

对于核心技能，建议要求：

```text
核心必备技能：至少 L2 或 L3
普通技能：L1 可接受
加分技能：出现即可加分
```

例如：

```json
{
  "skill": "PyTorch",
  "jd_importance": 5,
  "resume_evidence_level": 3,
  "score": 0.85,
  "evidence": "项目中使用 PyTorch 训练 YOLOv8 模型"
}
```

# 七、字段匹配规则

字段匹配适合处理明确、结构化的信息。

## 1. 学历匹配

```text
博士 > 硕士 > 本科 > 大专 > 高中
```

规则示例：

```python
if resume_degree >= jd_min_degree:
    degree_score = 1.0
else:
    degree_score = 0.0
```

## 2. 年限匹配

```python
if resume_years >= jd_min_years:
    years_score = 1.0
elif resume_years >= jd_min_years * 0.8:
    years_score = 0.7
elif resume_years >= jd_min_years * 0.5:
    years_score = 0.4
else:
    years_score = 0.0
```

## 3. 专业匹配

可以做专业归类：

```text
计算机类：
  - 计算机科学与技术
  - 软件工程
  - 人工智能
  - 数据科学
  - 网络工程

电子信息类：
  - 电子信息工程
  - 通信工程
  - 自动化
  - 控制工程

机械/电气类：
  - 电气工程
  - 机械工程
  - 车辆工程
```

例如 CV 算法岗：

```text
计算机/人工智能：1.0
电子信息/自动化/控制：0.8
数学/统计：0.7
机械/电气但有算法项目：0.6
完全无关专业：0.2
```

# 八、关键词匹配规则

关键词匹配不能直接决定最终结果，但可以作为底层特征。

## 1. 技能同义词归一

```json
{
  "PyTorch": ["torch", "pytorch", "深度学习框架"],
  "目标检测": ["object detection", "检测模型", "YOLO", "Faster R-CNN", "DETR"],
  "图像分割": ["segmentation", "semantic segmentation", "Mask R-CNN", "U-Net", "SAM"],
  "大模型": ["LLM", "GPT", "LLaMA", "Qwen", "ChatGLM", "GLM"],
  "向量检索": ["embedding", "Faiss", "Milvus", "RAG", "vector database"]
}
```

## 2. 精确匹配与模糊匹配结合

```text
Python == Python：强匹配
PyTorch ≈ torch：强匹配
目标检测 ≈ YOLO：强相关
图像处理 ≠ 计算机视觉算法：弱相关
机器学习 ≠ 深度学习工程经验：弱相关
```

# 九、Embedding 语义匹配

关键词匹配解决不了这类问题：

JD 写：

> 有工业缺陷检测经验优先。

简历写：

> 基于工业相机采集产品表面图像，训练模型识别划痕、污渍和裂纹。

这时候关键词不完全一样，但语义高度相关。

## 1. 做法

将 JD 的每条要求和简历中的经历片段分别向量化。

```text
JD requirement:
“有工业缺陷检测经验优先”

Resume evidence:
“基于工业相机采集产品表面图像，训练模型识别划痕、污渍和裂纹”
```

计算 embedding 相似度：

```text
similarity = cosine(jd_requirement_embedding, resume_evidence_embedding)
```

## 2. 相似度阈值建议

|         相似度 | 判断           |
| ----------: | ------------ |
|      ≥ 0.85 | 高度匹配         |
| 0.75 - 0.85 | 较匹配          |
| 0.65 - 0.75 | 可能相关，需要大模型复核 |
| 0.50 - 0.65 | 弱相关          |
|      < 0.50 | 不匹配          |

# 十、大模型语义推断规则

大模型不要直接给总分，而是做“证据判断”。

建议让大模型判断每个 JD 要求是否被简历支持：

```json
{
  "requirement": "熟悉目标检测算法，有 YOLO 系列模型经验",
  "resume_evidence": [
    "项目：无人机绝缘子检测，使用 YOLOv8 训练检测模型",
    "对小目标样本进行数据增强，mAP 提升 4.2%"
  ],
  "judgement": "supported",
  "confidence": 0.92,
  "reason": "简历明确出现 YOLOv8 目标检测项目，并有指标提升"
}
```

判断类型建议分为：

```text
supported：简历明确支持
partially_supported：部分支持
not_supported：不支持
contradicted：简历内容与要求冲突
insufficient_evidence：证据不足
```

# 十一、必备条件匹配规则

必备条件权重最高，建议单独建模。

## 1. 必备条件评分

```python
must_score = sum(requirement_score_i * importance_i) / sum(importance_i)
```

其中：

```text
明确满足：1.0
部分满足：0.6
弱相关：0.3
不满足：0.0
冲突：-0.5
```

## 2. 必备条件通过标准

```text
must_score >= 0.8：通过
0.6 <= must_score < 0.8：进入人工复核
must_score < 0.6：淘汰
```

## 3. 核心必备项一票否决

某些条件不能平均：

```json
{
  "requirement": "必须有推荐系统召回/排序经验",
  "is_knockout": true
}
```

如果候选人没有相关经验：

```text
直接淘汰，不进入综合评分。
```

# 十二、项目经验匹配规则

项目经验比技能栏更重要。

## 1. 项目相关性评分

```text
项目方向相关性：30%
技术方法相关性：30%
任务目标相关性：20%
结果指标可信度：20%
```

例如 JD 是“无人机视觉算法工程师”：

| 简历项目         |  匹配度 |
| ------------ | ---: |
| 无人机电力巡检小目标检测 | 0.95 |
| 工业相机缺陷检测     | 0.75 |
| 普通图像分类项目     | 0.55 |
| Java 后端管理系统  | 0.10 |

## 2. 项目证据质量

| 项目描述                                  | 可信度 |
| ------------------------------------- | --: |
| “负责 YOLOv8 小目标检测，mAP 从 82.1 提升到 86.3” |   高 |
| “参与目标检测模型优化”                          |   中 |
| “熟悉目标检测”                              |   低 |
| “了解深度学习”                              |  很低 |

# 十三、岗位职责匹配规则

把 JD 职责拆成一条一条，然后匹配简历经历。

例如 JD 职责：

1. 负责图像数据清洗、标注和增强

2. 训练过 YOLOv8 模型
3. 没有部署经验
4. 做过无人机巡检场景实验

```json
{

  "model_training": 1.0,
  "deployment": 0.0,
  "business_scenario": 0.8
}
```

# 十五、成果质量评分

不要只看“做过”，还要看“做得怎么样”。

## 1. 加分项

```text
有明确指标提升：+2 到 +5
有论文/专利：+1 到 +5
有竞赛获奖：+1 到 +4
有 GitHub 项目：+1 到 +3
有真实业务落地：+3 到 +5
有复杂系统搭建经验：+2 到 +5
```

## 2. 指标可信度

| 描述                  | 可信度 |
| ------------------- | --: |
| mAP 从 75.3 提升到 81.6 |   高 |
| 推理速度提升 35%          |   高 |
| 获得业务上线              |   高 |
| 效果较好                |   低 |
| 大幅提升                |   低 |
| 熟悉/了解               |   低 |

# 十六、风险项识别

大厂粗筛通常也会识别风险点。

## 1. 简历空窗期

```text
连续空窗超过 6 个月：轻度风险
连续空窗超过 12 个月：中度风险
多段不明空窗：需要人工复核
```

## 2. 跳槽频率

```text
连续多段工作 < 6 个月：风险增加
实习经历短不算严重风险
校招候选人不适用该规则
```

## 3. 经历描述过泛

例如：

```text
熟悉机器学习
了解深度学习
参与模型优化
负责算法研发
```

但没有数据集、模型、指标、任务目标、实验结果，则可信度下降。

## 4. 技能堆砌

技能栏写了很多：

```text
Python、Java、C++、Go、Rust、PyTorch、TensorFlow、Kubernetes、MySQL、Redis、Spark、Hadoop、Vue、React……
```

但项目中没有对应证据，应标记为：

```text
技能可信度不足
```

# 十七、最终评分公式

可以这样设计：

```text
Final Score =
  0.35 * 必备条件分
+ 0.20 * 技能栈匹配分
+ 0.20 * 项目/工作经验分
+ 0.10 * 岗位职责匹配分
+ 0.05 * 行业背景分
+ 0.05 * 教育/证书分
+ 0.05 * 成果质量分
- 风险扣分
```

风险扣分：

```text
轻微风险：-2
中度风险：-5
严重风险：-10
核心条件缺失：直接淘汰
```

# 二十、伪代码

```python
def resume_jd_match(resume_text, jd_text):
    jd = extract_jd_structure(jd_text)
    resume = extract_resume_structure(resume_text)

    jd = normalize_jd(jd)
    resume = normalize_resume(resume)

    hard_result = hard_filter_check(resume, jd)

    if not hard_result["pass"]:
        return {
            "final_score": 0,
            "decision": "reject",
            "reason": hard_result["failed_reasons"]
        }

    must_score = score_must_have(resume, jd)
    skill_score = score_skills(resume, jd)
    experience_score = score_experience(resume, jd)
    responsibility_score = score_responsibilities(resume, jd)
    domain_score = score_domain(resume, jd)
    education_score = score_education(resume, jd)
    achievement_score = score_achievements(resume, jd)

    risk_penalty = calculate_risk_penalty(resume)

    final_score = (
        35 * must_score +
        20 * skill_score +
        20 * experience_score +
        10 * responsibility_score +
        5 * domain_score +
        5 * education_score +
        5 * achievement_score -
        risk_penalty
    )

    recommendation = get_recommendation(final_score, must_score)

    return {
        "final_score": final_score,
        "recommendation": recommendation,
        "dimension_scores": {
            "must_have": must_score,
            "skills": skill_score,
            "experience": experience_score,
            "responsibilities": responsibility_score,
            "domain": domain_score,
            "education": education_score,
            "achievements": achievement_score
        },
        "evidence": collect_matching_evidence(resume, jd),
        "weaknesses": collect_weaknesses(resume, jd),
        "risks": collect_risks(resume)
    }
```

# 二十二、严格匹配与推断的边界

这点很重要，粗筛系统最容易出问题的地方就是“过度推断”。

## 可以合理推断

```text
简历写：使用 YOLOv8 完成无人机绝缘子检测
可以推断：候选人有目标检测项目经验

简历写：使用 PyTorch 训练深度学习模型
可以推断：候选人具备 PyTorch 基础使用经验

简历写：对模型进行量化、剪枝、ONNX 导出
可以推断：候选人有一定部署优化经验
```

## 不应该强行推断

```text
简历写：熟悉深度学习
不能推断：熟练掌握 PyTorch

简历写：做过图像处理
不能推断：做过目标检测

简历写：参与算法项目
不能推断：主导模型研发

简历写：了解大模型
不能推断：有 RAG 或 Agent 落地经验
```

# 二十四、一个更接近“大厂粗筛”的核心原则

真正粗筛不是“谁写的关键词多谁高分”，而是看这四件事：

```text
1. JD 的核心必备项是否明确满足
2. 简历中是否有真实经历支撑这些能力
3. 经历是否和岗位职责、业务场景接近
4. 候选人的能力强度是否达到岗位级别
```

所以最终判断逻辑应该是：

```text
关键词只是线索；
项目经历才是证据；
成果指标提升可信度；
核心条件缺失直接淘汰；
模糊情况进入人工复核。
```

这套规则已经可以直接扩展成一个“简历-JD 匹配系统”的开题方案或项目原型。
